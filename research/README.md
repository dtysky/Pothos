# Research

这里存放不隶属于大型项目的单次调研、行前案头研究和专题资料整理。

它适合承接一次明确的问题、旅程、地点、作品或主题，但不默认沉淀为长期知识库，也不默认升级为一个完整创作项目。

## 使用场景

- 某次旅行或拍摄前的文学、历史、地理、社会背景调研
- 某个主题的临时资料包，例如一座城市、一条路线、一组作品
- 尚未确定是否会发展成大型项目的前期研究
- 一次对话中形成的可复用报告，但还不适合写入 `.pothos/knowledge/`

## 与其他目录的边界

- `.pothos/knowledge/`：长期稳定、后续反复调用的人物、文风和项目方法论。
- `projects/*/research/`：已经归属某个大型项目的研究资料。
- `notes/`：咨询过程、判断记录、阶段性讨论归档。
- `research/`：独立的单次调研报告和专题案头资料。

## 命名规则

优先使用：

```text
YYYYMMDD-topic-scope.md
```

若明确承接 Pharos 行程创作资料包，Pothos 只保存 Markdown dossier。Markdown 是研究
真相源；`pharos/field-guide/v1` JSON 由 Pharos 从确认版 dossier 编译、维护、校验和
发布，Pothos 不创建或修改任何 Pyxis JSON。

Pharos 派发的研究默认在以完整旅程名称命名的 Pothos 会话中交互完成。Pothos 先分批提供
候选资料，由用户保留、暂存、排除或重新归类；只有用户明确说“交回 Pharos”之后，才把
已确认材料收束为 dossier 与交回摘要。会话讨论、未确认候选和阅读进度都不进入 Pyxis。

示例：

```text
20260617-hebei-wanqing-taihang-industrial.md
```

如果调研没有明确日期，可以使用：

```text
topic-scope.md
```

## 写作要求

- 明确区分事实、推断和建议。
- 外部资料需要保留来源链接或出处。
- 避免堆砌摘录，优先写成可直接用于创作判断的结论。
- 行前资料优先采用“综述—分地点—结论”，但地点内部不套用固定栏目。自然基础、历史与
  生活、当代处境、饮食与物产只作为调研检查表，成文时按地点实际特点取舍。
- 旅程长度决定选题数量，不决定已选问题的知识完整度。重点自然地点应按实际需要交代地质
  年代与演化、水系源流和水文特征；重点人文地点应建立必要的历史时间层次。
- 饮食部分尽量收录已有可靠资料的全部地方代表品类，分组简要说明，再重点展开少数最有
  辨识度和地方解释力的食物；不推荐具体商家。
- 正文首先是资料调研报告，以事实、演变和解释为主。“应该看什么、拍什么、怎样取舍”等
  行程建议集中放在结论或独立小节，不穿插在知识正文中。
- 不把观察、采访和拍摄写成必须完成的任务，也不使用抒情游记、VLOG 口吻或解释写作过程
  的元话语。
- 如果后续发展为大型项目，应迁移到 `projects/<project-code>/research/`，并在这里保留迁移说明或索引。
